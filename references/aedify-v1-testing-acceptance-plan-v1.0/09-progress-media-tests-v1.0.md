## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.

## Media Session Types

Supported v1 sessions:

- Photo set: front, back, left side, right side.
- Short all-sides video.
- Mixed session if product UI allows both.
- Optional notes.
- Optional bodyweight/measurement snapshot if implemented.

## Permission Tests

| Platform | Case | Expected Result |
|---|---|---|
| iOS | Camera granted | Capture works. |
| iOS | Camera denied | Clear settings/help state. |
| iOS | Photo library limited | User can select allowed media or sees clear limitation. |
| iOS | Microphone denied for video | Video path handles audio requirement or records silent if allowed. |
| Android | Camera granted | Capture works. |
| Android | Camera denied | Clear settings/help state. |
| Android | Media/gallery permission denied | Import path blocked with guidance. |
| Android | Health/notification permission unrelated | Does not block media capture. |

## Photo Session Tests

Test cases:

1. Capture front photo.
2. Capture back photo.
3. Capture left-side photo.
4. Capture right-side photo.
5. Import four existing photos.
6. Save complete photo session.
7. Save partial photo session if allowed by UI.
8. Retake one angle before save.
9. Delete one photo before save.
10. Cancel session before save.

Expected:

- Raw files saved in app sandbox only after required save point.
- Metadata written to Drift.
- Thumbnails generated or fallback shown.
- Angle labels persist.
- Cancel cleans temporary files.

## Video Session Tests

Test cases:

- Capture short all-sides video.
- Import short video.
- Reject or warn for oversized/too-long video.
- Generate thumbnail.
- Extract representative frames later for AI analysis only after consent.
- Playback preview works or fails gracefully.
- Delete video session removes video and thumbnail metadata/files.

Expected:

- Video size/duration controls prevent uncontrolled local storage growth.
- Video file path never appears in Crashlytics.
- Video is excluded from exports.

## Reminder Tests

Rules:

- Reminder cadence prompt appears only after first saved progress media session.
- Supported cadence: every 2 weeks, monthly, every 3 months, off.
- Reminders use local notifications only.

Test cases:

1. New user with no media: no reminder prompt.
2. Save first media session: prompt appears.
3. Choose every 2 weeks: schedule created.
4. Choose monthly: schedule updated.
5. Choose every 3 months: schedule updated.
6. Choose off: schedule cancelled.
7. Delete latest media session: reminder behavior follows product rule; no orphaned invalid notification.
8. Notification permission denied: clear disabled state.

## Storage + Cleanup Tests

Test cases:

- Delete session deletes metadata and files.
- Delete app data removes media files.
- Failed thumbnail generation leaves raw media intact but records fallback.
- File missing but metadata exists shows recoverable broken-media state.
- Metadata missing but orphan file exists cleanup job removes or ignores according to retention policy.
- Low storage blocks new video capture or warns user.

## Privacy Exclusion Tests

Progress media must not appear in:

- Crashlytics.
- `.aedifyplan` exports.
- PDF exports.
- External import payloads.
- AI prompts unless explicit physique-analysis consent later occurs.
- Debug logs.
- Candidate lists.

Test method:

- Create media session with synthetic file names and notes.
- Run export/share flows.
- Trigger fake crash.
- Inspect generated files/logs/test Crashlytics payload.

Expected:

- No media paths, thumbnails, raw media, extracted frames, analysis results, or notes leak where forbidden.

## Offline Tests

- Capture/import media offline.
- View media history offline.
- Edit notes offline.
- Delete media offline.
- Reminder scheduling offline.

Expected:

- All non-AI progress media features work offline.
