## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.

## Analytics Data Rules

- Working sets drive default strength analytics.
- Warm-up sets are visible in history but excluded from PRs, e1RM, plateau detection, progression triggers, and default volume analytics.
- Deleted/cancelled workouts must not contribute.
- Incomplete active workouts must not contribute.
- Corrected completed logs must update derived analytics.
- Unit display conversion must not alter canonical stored values.

## PR Detection Tests

### Strength PR Cases

| Case | Fixture | Expected Result |
|---|---|---|
| Heavier weight same reps | Previous 100×5, new 105×5 | New PR. |
| Same weight more reps | Previous 100×5, new 100×6 | New rep PR. |
| Lower weight more reps | Previous 100×5, new 90×8 | Depends on PR type/e1RM; deterministic output. |
| Warm-up heavier than old work | Warm-up set only | Not PR. |
| Failed set | Completed false or missed reps flag | Not PR unless policy allows completed value. |
| Bodyweight exercise | Reps/time progression | Uses defined bodyweight PR rule. |
| Cardio exercise | Time/distance/speed if in scope | Uses modality-specific rule. |

### Edge Cases

- First logged set creates baseline PR if policy says so.
- Tie does not create duplicate PR unless new date/history marker required.
- Correcting old workout may recalculate PR timeline.
- Deleting workout removes dependent PR or recomputes prior PR.

## Plateau Detection Tests

Plateau logic must be deterministic and AI-independent.

Required fixtures:

| Fixture | Expected Result |
|---|---|
| Sufficient history, no progress, repeated misses | Plateau candidate. |
| Insufficient history | No candidate; needs more data. |
| Recent deload | No false plateau or lower confidence. |
| Progress still occurring | No candidate. |
| Warm-up-only data | No candidate. |
| Exercise substituted out | No candidate or flagged as inactive. |
| Injury note present | Candidate may be suppressed or warning shown depending rules. |
| High RPE/missed reps | Candidate reason includes fatigue/recovery signal. |

Acceptance:

- Detector emits reason codes, not AI text.
- Detector does not call provider.
- AI suggestion flow later consumes only scoped candidate context.
