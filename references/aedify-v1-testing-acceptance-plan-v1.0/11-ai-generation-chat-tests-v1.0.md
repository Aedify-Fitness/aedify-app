## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.

## AI Workout Generation Tests

### Happy Paths

| Case | Expected Result |
|---|---|
| Beginner general workout | Simple prescription, valid exercise IDs, no AI-generated supersets. |
| Beginner with equipment constraints | Hard equipment filter respected. |
| Non-beginner hypertrophy workout | Appropriate volume, valid set-level prescriptions. |
| Non-beginner strength workout | Warm-up sets for priority loaded compound lifts where required. |
| Non-beginner strength + hypertrophy | Powerbuilding reference allowed only if eligible; fatigue management present. |
| Workout from chat save intent | Routed to structured flow and review before save. |

### Negative Paths

- Missing BYOK key.
- Missing network.
- Provider timeout.
- Missing required profile fields.
- Build Strength with no useful anchor/bodyweight where required.
- Candidate list empty.
- AI returns invalid JSON.
- AI returns exercise outside candidate list.
- AI includes beginner superset.
- AI includes unsafe/injury-conflicting exercise.

Expected:

- No partial workout is persisted.
- User receives safe error or needs-input state.
- Repair attempt follows rules.

## Multi-Week Programme Generation Tests

Required fixtures:

1. Beginner Path A strict wiki-derived structure.
2. Beginner custom generation with conservative rules.
3. Intermediate strength programme.
4. Intermediate hypertrophy programme.
5. Intermediate strength + hypertrophy powerbuilding-style programme.
6. Fat loss/general fitness programme with resistance training and conditioning.
7. Limited equipment programme.
8. Injury/substitution constrained programme.

Validation assertions:

- Programme duration follows PRD rules unless import-specific exception applies.
- Template-based output expands safely at save time.
- Weeks/days/templates are internally consistent.
- Set-level prescriptions exist.
- Warm-up/working set types are present.
- Beginner AI programme has no supersets.
- Non-beginner accessory supersets are valid if used.
- Deload rules present where required.
- Progression rules apply to working sets, not warm-ups.
- Exercise IDs are valid and candidate-approved.
- No local DB IDs are invented.

## Review-Before-Save Tests

Scenarios:

- User previews generated workout and saves.
- User previews generated workout and cancels.
- User edits generated draft before save if allowed.
- User rejects generated programme.
- App killed on preview screen.
- Save transaction fails after validation.

Expected:

- No generated item persists until explicit save.
- Cancel leaves no active programme.
- Save failure leaves recoverable draft or safe error without partial active programme.

## AI Chat Tests

### Conversational Chat

Cases:

- Ask general training question.
- Ask nutrition/supplement question within educational scope.
- Ask medical/injury diagnosis question.
- Ask to save a workout explicitly.
- Ask vague “make me something” without save intent.

Expected:

- Normal chat remains conversational.
- Medical/injury diagnosis is redirected to qualified professional.
- Save intent routes to structured generation and review.
- Chat does not persist by itself.

## AI Update Flow Tests

### Exercise Swap

- Valid swap with candidate list.
- Swap avoids substituted/injured movement.
- AI suggests exercise outside candidate list.
- User accepts swap.
- User rejects swap.
- Swap affects future scheduled workout but not historical completed logs.

### Deload

- Generate deload for current week.
- Validate reduced volume/intensity rules.
- Preserve movement patterns where possible.
- User accepts/rejects.
- Deload does not progress load.

### Plateau Suggestion

- Deterministic plateau candidate triggers AI suggestion.
- AI receives scoped plateau context.
- Suggestion is advisory or structured update depending flow.
- User applies suggested programme change only after review.

## Safety + Source Integrity Tests

- Beginner generation excludes powerbuilding reference.
- Powerbuilding output does not reproduce source tables or branded phases.
- AI does not present exact paid programme reconstruction.
- AI avoids extreme dieting advice.
- AI does not prescribe around injuries without clearance.
- AI does not claim medical authority.
