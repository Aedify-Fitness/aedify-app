## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.


## Privacy Threat Model for v1

Primary risks:

1. BYOK API key leakage.
2. Prompt/AI response leakage.
3. Training logs or health-like data appearing in crash reports.
4. Injuries/limitations appearing in logs or exports.
5. Progress media paths or files escaping local sandbox.
6. Imported source content being re-exported.
7. Image import screenshots/enhanced artifacts being retained or shared.
8. AI physique analysis being framed as precise/medical.
9. `shared_preferences` used for critical or sensitive data.
10. Raw local DB rows serialized into exports.

## Crashlytics Redaction Tests

Allowed crash context:

- App version.
- OS version.
- Device model.
- Screen name.
- Non-sensitive feature flags.
- Local schema version.
- Exercise dataset version.
- Error code.
- Redacted stack trace.

Forbidden crash context:

- API keys.
- Prompt text.
- AI responses.
- Chat history.
- Structured output JSON.
- Candidate lists.
- Injuries/limitations.
- Lift logs/set logs.
- Body measurements.
- Progress media paths/files.
- Source files/excerpts.
- Original/enhanced screenshots.
- Image artifacts.
- Local database dumps.
- User free-form notes.

Test cases:

- Crash during workout logging.
- Crash during AI generation.
- Crash during external import.
- Crash during image import.
- Crash during progress media capture.
- Crash during PDF export.
- Crash during secure storage read.

Expected:

- Crash contains useful error code/screen context only.
- Sensitive sentinel strings absent.

## Export Privacy Tests

Sentinel injection:

- Profile name: `SENTINEL_PROFILE_PRIVATE`.
- Injury note: `SENTINEL_INJURY_PRIVATE`.
- Log note: `SENTINEL_LOG_PRIVATE`.
- Prompt: `SENTINEL_PROMPT_PRIVATE`.
- Raw response: `SENTINEL_RAW_AI_PRIVATE`.
- Source file excerpt: `SENTINEL_SOURCE_PRIVATE`.
- Screenshot text: `SENTINEL_SCREENSHOT_PRIVATE`.
- Media path: `SENTINEL_MEDIA_PRIVATE`.

Run exports:

- `.aedifyplan` template.
- `.aedifyplan` exact prescription.
- PDF.
- Native share output files.

Expected:

- Only allowed local plan prescription fields appear.
- All forbidden sentinels absent.

## AI Payload Minimization Tests

For each operation, verify payload contains only allowed context:

| Operation | Must Exclude By Default |
|---|---|
| External text import parse | Full profile, logs, injuries, measurements, chat history. |
| Image import parse | Full profile, logs, injuries, unrelated media, chat history. |
| Physique analysis | Logs, full profile, unrelated progress media. |
| Chat | Source screenshots, raw local DB dumps, API keys. |
| Generation | API keys, unrelated import source files, progress media. |
| Repair | Unneeded profile/log data unless required by schema repair. |

## Local File Security Tests

- Progress media stored in app sandbox.
- Import temporary files stored in temp/import area.
- Enhanced images are temporary.
- Export files use temporary/share-safe location and cleanup policy.
- File names do not include sensitive notes/profile data.
- Delete operations remove files and metadata.

## `shared_preferences` Audit

Before release:

- Dump registered preference keys.
- Classify each key as non-critical/recoverable.
- Confirm no keys contain secrets, logs, programmes, imports, AI outputs, progress media records, schema-critical data.
