## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.

## Unit Test Requirements

### Riverpod Provider Graph

Test cases:

1. Provider graph boots with fake dependencies.
2. Provider overrides can replace database, secure storage, preferences, network, AI, and file services.
3. Feature controllers do not depend directly on `BuildContext`.
4. Controllers expose loading/success/error states deterministically.
5. Provider disposal does not leak subscriptions or file handles.
6. Long-running tasks can be cancelled without writing partial data.

Acceptance:

- All feature controllers can be instantiated in tests.
- No controller requires real Firebase, real secure storage, or real AI provider for unit tests.

### Storage Boundary Tests

Test cases:

| Case | Expected Result |
|---|---|
| Write simple theme setting to preferences | Allowed. |
| Write onboarding complete flag to preferences | Allowed if non-critical and recoverable. |
| Attempt to write API key to preferences | Fails by wrapper design, test convention, or code review guard. |
| Attempt to write API key to Drift | No repository path exists. |
| Write BYOK key to secure storage | Allowed. |
| Delete BYOK key | Key removed; AI features disabled. |
| Secure storage read failure | User sees recoverable provider setup error. |
| Store programme in Drift | Allowed. |
| Store progress media raw bytes in Drift | Not allowed; only metadata path stored. |

Acceptance:

- Secrets are never duplicated outside secure storage.
- Durable structured data is not stored in `shared_preferences`.

## Drift Database Tests

### Schema Creation

Test cases:

1. Fresh install creates all tables.
2. Singleton metadata rows are created or lazily initialized.
3. Foreign keys are enabled.
4. Indexes exist for high-frequency queries.
5. Required columns reject null.
6. Enum columns reject unsupported values via mapper/validator.

Acceptance:

- Fresh DB opens without migration errors.
- Schema introspection matches expected schema version.

### Transaction Tests

Required transaction scenarios:

- Create programme with templates, days, exercises, and set prescriptions.
- Complete workout with set logs, notes, PR candidate updates, and active workout status update.
- Import `.aedifyplan` with custom exercises and programme clone.
- Save external import after unresolved exercise resolution.
- Delete progress media session metadata and file records.

Failure injection:

- Throw during child insert.
- Throw during final status update.
- Throw during file metadata write.
- Throw during custom exercise mapping.

Expected:

- No partial parent/child rows remain.
- Existing active data remains valid.
- User receives recoverable error.

### Migration Tests

Required migrations:

1. Empty → current.
2. Current → current no-op.
3. Older seeded schema with basic programmes → current.
4. Older seeded schema with logs → current.
5. Older seeded schema with progress media metadata → current.
6. Failed migration rollback where possible.

Acceptance:

- No data loss for supported migrations.
- Unsupported migration shows safe update/recovery state rather than corrupting data.

## Local File Service Tests

Test cases:

- Resolve app documents directory.
- Resolve temporary import directory.
- Resolve progress media directory.
- Write test file.
- Delete test file.
- Delete missing file safely.
- Cleanup expired temporary artifacts.
- Handle permission/path failure.

- File paths are not exposed in Crashlytics/logs when sensitive.
- Media and import artifacts are segregated by feature.
- Cleanup does not delete durable user files accidentally.

## Logging + Crashlytics Tests

### Redaction Inputs

Inject payloads containing:

- Fake API key.
- Prompt text.
- AI response JSON.
- Candidate exercise list.
- Injury note.
- Lift log note.
- Body measurement.
- Progress media path.
- Screenshot file path.
- Source-file excerpt.
- Local DB dump-like string.

Expected:

- Logs redact or omit payload.
- Crashlytics custom keys contain only allowed metadata.
- Error code and screen name remain available.
- No raw sensitive value appears in captured output.

## App Bootstrap Integration Tests

### Fresh Install Smoke

Steps:

1. Install app fresh.
2. Launch app.
3. Verify DB initializes.
4. Verify app routes to onboarding or dataset-needed screen.
5. Kill app.
6. Relaunch.

Expected:

- No crash loop.
- No duplicate schema initialization.
- No fake/debug-only data in release-mode configuration.

### Offline Launch Smoke

Steps:

1. Fresh install.
2. Disable network.
3. Launch app.

Expected:

- App shows clear offline/dataset unavailable state.
- App does not crash.
- App does not attempt AI calls.

### Upgrade Smoke

Steps:

1. Install seeded older build/database.
2. Upgrade to current build.
3. Launch app.
4. Verify migration.
5. Verify programmes/logs/media metadata still accessible.

Expected:

- Migration succeeds or safe failure is shown.
- No duplicate rows.
- No orphaned critical records.
