## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.

## Accessibility Tests

### Screen Reader

Test with VoiceOver/TalkBack:

- Onboarding fields.
- Profile/settings.
- Exercise search/filter.
- Exercise detail steps.
- Bodymap fallback/labels.
- Workout builder.
- Active workout logger.
- AI consent screens.
- Import review screens.
- Progress media session list.
- Export options.

Acceptance:

- Controls have meaningful labels.
- Consent warnings are read clearly.
- User can complete core workout logging with screen reader.
- Bodymap has accessible alternative selection list if SVG interaction is not enough.

### Font Scaling

Test:

- Default.
- Large text.
- Maximum practical text size.

Critical screens:

- Active workout logger.
- AI/import validation errors.
- Consent screens.
- Exercise detail.
- Programme preview.

Expected:

- Text not clipped in critical actions.
- Buttons remain reachable.
- Scroll views handle overflow.

### Tap Targets + Contrast

- Minimum tap target respected.
- Dark/light mode contrast for charts/bodymap/buttons.
- Disabled AI gates visually and semantically clear.

## Performance Tests

### Startup

Scenarios:

- Fresh install no dataset.
- Synced dataset.
- Large local DB with logs/media metadata.
- Offline startup.

Acceptance:

- No long blank screen.
- Loading states are clear.
- No startup crash with missing media files.

### Dataset + Library

- Full dataset parse/persist.
- Search latency with full dataset.
- Filter changes.
- Bodymap filter.
- Exercise detail open.

### Logging

- Active workout screen with large workout.
- Rapid set logging.
- App background/foreground.
- Completion transaction.

### Media

- Save photo session.
- Save short video.
- Generate thumbnail.
- Delete large media session.
- Low storage handling.

### AI

- Prompt assembly time with large candidate list within caps.
- Validation time for large programme output.
- Repair flow timeouts/cancellation.
- Image import payload size checks.

## Resilience Tests

Interruption scenarios:

- App killed during dataset sync.
- App killed during programme save.
- App killed during active workout.
- App killed during export generation.
- App killed during external import draft.
- App killed during image enhancement.
- App killed during progress media save.
- Device offline mid-AI call.
- Low battery/background restrictions.

Expected:

- No corrupted durable state.
- Temporary artifacts cleaned or recoverable.
- User can resume or restart safely.
- No duplicate completed workouts/programmes.
