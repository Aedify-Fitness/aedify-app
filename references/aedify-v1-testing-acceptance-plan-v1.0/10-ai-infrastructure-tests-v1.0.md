## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.

## Provider Adapter Tests

### Common Adapter Behavior

Test cases:

- Adds provider auth header at request time only.
- Does not log auth header.
- Maps auth failure to user-readable invalid key state.
- Maps rate limit to user-readable cost/rate message.
- Maps timeout to retryable failure.
- Supports cancellation.
- Handles malformed provider response.
- Handles provider safety/block response.
- Handles network offline state.

Acceptance:

- No provider adapter exposes raw key to logs/errors.
- Provider-specific errors are normalized into app-level error codes.

### Retrofit vs Hand-Written Dio Boundaries

Tests:

- Stable REST-style capability calls can use Retrofit where implemented.
- Complex AI generation payloads can use hand-written Dio adapter without breaking shared error handling.
- Multipart/image payloads do not force awkward Retrofit use if hand-written path is safer.

## Capability Gate Tests

Capabilities:

- `supports_text_input`.
- `supports_native_json_mode` or equivalent.
- `supports_image_input`.
- Max image count/size where available.
- Provider/model availability.

Scenarios:

| Scenario | Expected Result |
|---|---|
| Text-only model | Chat/generation enabled; image import/physique disabled. |
| Text + JSON model | Structured outputs use native mode where adapter supports. |
| Image-capable model | Image import/physique paths enabled after consent. |
| Unknown model | Conservative disabled/needs verification state. |
| Capability check offline | Existing cached capability used only if safe; otherwise prompt reconnect. |
| Capability changes after key rotation | Gates refresh. |

## Prompt Builder Tests

Prompt builder must include only required sections.

Test snapshots:

- AI chat prompt.
- Daily workout prompt.
- Multi-week programme prompt.
- Beginner Path A prompt.
- Strength + hypertrophy eligible prompt.
- Exercise swap prompt.
- Deload prompt.
- Plateau suggestion prompt.
- External text import parse prompt.
- Image import parse prompt.
- Physique analysis prompt.
- Structured output repair prompt.

For each snapshot assert:

- Correct instruction modules included.
- Full profile excluded where import flow requires exclusion.
- Injuries included only where needed and never logged.
- Candidate list present only where needed.
- Schema included for app-actionable structured outputs.
- Image import includes only image package metadata/instructions after consent.
- Progress media analysis includes only selected media/frames after consent.

## Structured Output Validation Tests

Validation layers:

1. JSON parse.
2. Shared envelope validation.
3. Response type and schema version validation.
4. Schema-specific structural validation.
5. Business-rule validation.
6. Exercise ID candidate validation.
7. Persistence-readiness validation.
8. Privacy/source-integrity validation.

Required invalid fixtures:

- Markdown wrapped JSON.
- Truncated JSON.
- Missing envelope.
- Wrong response type.
- Unsupported schema version.
- Invented exercise ID.
- Local DB ID invented.
- Missing set type.
- Warm-up exceeds 80% rule.
- Beginner AI superset.
- External import includes source excerpt.
- Image import guesses unreadable number.
- Physique output gives exact BF%.
- Response includes prompt/raw reasoning.

Expected:

- Invalid output is rejected.
- Repair attempted only when safe and allowed.
- Non-repairable output returns safe failure state.

## Repair Flow Tests

Rules:

- One automatic repair attempt by default.
- Second attempt requires user-triggered retry.
- Repair prompt receives validation errors, invalid JSON, expected schema, and candidate list where needed.
- Repair may not invent missing content.

Test cases:

1. Invalid JSON repair succeeds.
2. Missing field repair succeeds.
3. Invented exercise ID repair selects valid candidate only if intent clear.
4. Missing source content in import returns `needs_input`, not guessed content.
5. Image unreadable content remains flagged.
6. Repair fails; user sees safe error.
7. Automatic repair does not loop.

## Candidate Exercise Engine Tests

Required checks:

- Hard filter equipment.
- Hard filter experience.
- Soft rank goals.
- Include adjacent compatible movements where allowed.
- Exclude substituted/avoided exercises.
- Candidate caps per operation respected.
- Candidate payload contains required fields and no private notes.
- External import matching candidates scoped to unresolved names.

Acceptance:

- AI receives deterministic candidate list.
- Generated exercise IDs outside candidate list are rejected.

## AI Privacy Tests

Inject sensitive values into profile/log/import fixtures and verify:

- Prompt builder includes only allowed scoped data.
- Logs redact prompt/request/response.
- Crashlytics excludes prompts/responses/candidates.
- AI response snapshots are not persisted unless explicitly allowed as sanitized structured result.
- Error messages do not include raw provider body.
