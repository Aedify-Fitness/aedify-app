## Goal

Define the final release-readiness process for the private v1 build. The app is not a public launch; it is a controlled private release for a maximum of 5 users. The release process must prove stability, privacy, local data correctness, AI failure safety, and installation/update readiness.

## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.


## Release Candidate Entry Criteria

A build may become a release candidate only when:

- All milestone gates M0–M14 pass.
- All blocking defects are closed.
- No unreviewed product-scope changes exist.
- Data migrations pass from all seeded previous private-test schemas.
- AI fake-provider suite passes.
- At least one real text-provider smoke test passes if a key is available for QA.
- At least one real image-capable provider smoke test passes if available for QA; otherwise image paths are validated with fake provider and clearly marked for real-provider follow-up.
- Crashlytics redaction tests pass locally and in console verification.
- Export privacy sentinel tests pass.
- Fresh install works on both platforms.

## Final Smoke Test Script

Run on iOS and Android:

1. Fresh install.
2. Launch app online.
3. Complete onboarding.
4. Sync exercise dataset.
5. Search exercise library.
6. Open exercise detail.
7. Create manual workout.
8. Start workout.
9. Log warm-up and working sets.
10. Complete workout.
11. View workout history.
12. View analytics/PR baseline.
13. Create progress media session using synthetic media.
14. Export programme/workout as `.aedifyplan`.
15. Export PDF.
16. Import `.aedifyplan` back as inactive copy.
17. Configure fake or real BYOK provider.
18. Run AI capability check.
19. Generate AI workout with preview, then cancel.
20. Generate AI workout with preview, then save.
21. Run AI chat without save intent.
22. Run external text import using fixture.
23. Run image import using fixture/fake provider.
24. Run physique analysis using fixture/fake provider.
25. Trigger fake crash/error and verify redaction.
26. Disable network.
27. Confirm library/manual programmes/logging/progress media still work offline.

## Private Beta User Acceptance

Because v1 is private, acceptance should focus on practical usability rather than public metrics.

Minimum beta questions:

- Can the user onboard without help?
- Can the user find exercises?
- Can the user build/log a workout?
- Can the user understand AI setup requirements?
- Are AI failures understandable?
- Are import review screens clear?
- Are export warnings clear?
- Are progress media privacy/consent screens clear?
- Did the app crash?
- Did any data disappear unexpectedly?

## Release Blockers

Release is blocked if any of these are true:

- BYOK key leakage found.
- Crashlytics contains sensitive user/training/AI/media/source data.
- Manual workout logging unreliable.
- App cannot launch offline after sync.
- Exercise dataset sync corrupts or loses existing local library.
- AI output can be persisted without validation/review.
- Import can save unresolved exercises.
- Exports contain forbidden data.
- Progress media appears in exports/Crashlytics.
- Image import artifacts remain after lifecycle cleanup.
- App has a reproducible crash loop.
- Private distribution exceeds agreed user limit.

## Release Notes Requirements

Private release notes should mention:

- This is a private v1 build.
- Data is local to device by default.
- AI requires user's own provider key.
- AI provider may process data sent with consent.
- Progress media/AI analysis are optional.
- Some imports depend on file/image quality.
- Users should report crashes and data-loss issues immediately.

Do not overstate:

- AI accuracy.
- Physique/body-fat precision.
- Medical safety.
- Public availability.

## Post-Release Monitoring

For the private beta period, monitor:

- Crash rate and redacted crash categories.
- User-reported data loss.
- User-reported import parsing failures.
- User-reported confusing AI setup/gates.
- Permission issues.
- Media storage/deletion issues.
- Export/import compatibility issues.

Do not collect behavioral analytics or usage telemetry.
