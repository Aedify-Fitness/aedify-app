## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.


## Environment Types

| Environment | Purpose | Network | Data | AI |
|---|---|---|---|---|
| Local unit test | Pure logic and validators | None | In-memory fixtures | Fake only |
| Local repository test | Drift DAOs, transactions, migrations | None | Temporary SQLite/Drift DB | Fake only |
| Widget test | UI state and validation behavior | None by default | Fake repositories | Fake only |
| Integration simulator/emulator | Full app flows | Controlled on/off | Seeded local + Firebase test bucket | Fake/provider smoke |
| Real-device QA | Permissions, media, sharing, Crashlytics | Controlled on/off | Synthetic user data | Fake/provider smoke |
| Private release RC | Final build validation | Real network where needed | Fresh install + upgrade path | Real BYOK smoke only |

## Device Matrix

### iOS

Minimum required coverage:

- One current iPhone simulator for automated integration flows.
- One older supported iPhone simulator for layout and migration checks.
- One real iPhone for permissions, camera/gallery, video capture, local notifications, files/share sheet, HealthKit, and Crashlytics.

Manual checks:

- Fresh install.
- Upgrade from seeded previous schema.
- Airplane mode after exercise sync.
- Low-storage warning behavior where possible.
- App background/foreground during workout logging.
- App termination during media import or workout logging.

### Android

Minimum required coverage:

- One current Android emulator.
- One older supported Android emulator/API level aligned with the eventual minSdk.
- One real Android device for permissions, camera/gallery, video capture, local notifications, Android share sheet, Health Connect, file access, and Crashlytics.

Manual checks:

- Fresh install.
- Upgrade from seeded previous schema.
- Denied permissions.
- Limited photo/media permissions if platform supports it.
- App process kill during import/logging.
- Split-screen or font scaling where practical.

## Network Profiles

| Profile | Required Tests |
|---|---|
| Online stable | Initial Firebase dataset sync, AI provider smoke, video streaming. |
| Offline from launch | App shows clear dataset-unavailable onboarding state if no prior sync. |
| Offline after sync | Exercise library, programmes, logging, analytics, progress media, local sharing work. |
| Network drops during sync | Sync fails safely; previous dataset retained if present. |
| Network drops during AI call | AI call fails safely; no partial output persisted. |
| Slow network | User can cancel long-running AI/import sync; no duplicate writes. |
| Provider timeout | User-readable retry path; no raw provider response logged. |

## Test Fixtures

### Exercise Dataset Fixtures

Required fixtures:

1. `exercise_dataset_valid_v1.json`
   - Contains representative strength, cardio, flexibility, recovery exercises.
   - Contains videos, null mechanics, force values, grips, steps.
   - Contains all 14 UI muscle buckets.

2. `exercise_dataset_minimal_v1.json`
   - Minimum valid dataset for fast tests.

3. `exercise_dataset_future_compatible.json`
   - Simulates additive fields that should be ignored/migrated.

4. `exercise_dataset_future_unsupported.json`
   - Simulates `min_app_schema_version` above client capability.
   - Must trigger update-required state.

5. `exercise_dataset_invalid_mapping.json`
   - Contains unknown muscle/category values.
   - Must fail build-time or sync validation as applicable.

### Profile Fixtures

Required fixtures:

- Single saved workout with working sets only.
- Workout with warm-up + working sets.

- Non-beginner strength programme with warm-up sets.

### Logging Fixtures

Required fixtures:

- Completed workout with RPE/RIR.
- Missed reps and high RPE case.
- Warm-up sets excluded from analytics.
- PR candidate that should count.
- PR candidate that should not count.

### AI Response Fixtures

Required fixtures per response type:

- Valid response.
- Invalid JSON.
- Valid JSON with schema errors.
- Valid schema with business-rule violations.
- Repairable response.
- Non-repairable response.

Text file fixtures:

- Simple single-workout TXT.
- Multi-week Markdown programme.
- CSV workout with clear units.
- CSV with ambiguous units.
- XLSX with multiple sheets.
- Text-based PDF with tables.

- Analysis snapshot with rough range.

## Fake Services

### Fake Firebase Storage

Must simulate:

- Manifest fetch success.
- Manifest fetch timeout.
- Dataset download success.
- Dataset checksum/version mismatch.
- Future unsupported schema.
- Anonymous auth failure.
- Offline state.

### Fake Secure Storage

Must simulate:

- Store/read/delete BYOK key.
- Platform read failure.
- Key rotation.
- Missing key.
- Secure storage wipe.

Assertions:

- No fallback to shared preferences.
- No key mirrored into Drift.
- No key printed in logs.

### Fake AI Provider

Must simulate:

- Text-capable model.
- JSON/schema-capable model.
- Image-capable model.
- Non-image-capable model.
- Provider auth failure.
- Rate limit.
- Timeout.
- Malformed response.
- Oversized response.
- Safety/block response.
- Streaming unsupported path if not in v1.

### Fake File System

Must simulate:

- App documents directory.
- Temporary directory.
- Media directory.
- Low disk condition.
- File write failure.
- File delete failure.
- Permission denial.

## Golden Output Rules

Golden files are required for:

- `.aedifyplan` export DTOs.
- `.aedifyplan` import validation outputs.
- PDF export content structure, excluding pixel-perfect visual tests unless tooling supports stable rendering.
- AI structured-output validation results.
- Import draft normalization.
- Exercise candidate filtering/ranking.
- Crashlytics redaction output.
- Privacy export sanitization.

Golden files must be:

- Synthetic.
- Versioned with schema version in filename.
- Updated only with review.
- Free of real personal data.
- Free of API keys.
- Free of copied paid programme tables.

## Seeded Database States

Maintain seed builders for:

1. Empty install.
2. Synced library only.
3. Onboarded profile without BYOK.
4. Onboarded profile with fake BYOK capability.
5. Active programme with no logs.
6. Active programme with logs and PRs.
7. Import draft unresolved.
8. Progress media sessions with files.
9. Old schema requiring migration.
10. Corrupt partial transaction rollback case.

## CI Requirements

CI must run:

- `flutter analyze` or equivalent static analysis.
- Unit tests.
- Drift repository tests.
- JSON schema validation fixture tests.
- Import/export golden tests.
- Privacy redaction tests.

CI should not require:

- Real Firebase project.
- Real LLM provider key.
- Real camera/gallery.
- Real HealthKit/Health Connect.

## Manual Test Record Format

Each manual test run must record:

- Tester.
- Date.
- App build number.
- Platform/device/OS.
- Install type: fresh/upgrade.
- Network profile.
- Fixture/user profile used.
- Steps executed.
- Expected result.
- Actual result.
- Screenshots or logs with sensitive data redacted.
- Pass/fail.
- Defect ID if failed.
