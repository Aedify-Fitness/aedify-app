## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.

## Universal Milestone Exit Gate

Every milestone must pass this universal gate before being marked complete:

- Feature behavior matches the locked PRD and current roadmap order.
- No new product scope is silently introduced.
- All new data writes are transactional where required.
- All durable data is stored in the correct storage layer.
- All new repositories/controllers have unit or integration coverage.
- All user-facing errors are understandable and recoverable.
- Offline behavior is explicitly tested.
- Privacy redaction is tested for any new logging, crash, export, AI, import, or media path.
- iOS and Android both pass the milestone smoke test.
- No blocking defect remains open.

## M0 — Implementation Lock & Backlog Setup

### Exit Criteria

- All source documents are named, versioned, and linked from the implementation workspace.
- Roadmap v1.3 sequencing is reflected in task hierarchy.
- Every major feature area maps to at least one backlog epic.
- Every epic references PRD sections or implementation-plan sections.
- Change-control rule is visible: future product changes require formal request/version bump.
- Test strategy exists before feature coding begins.

### Blocking Failures

- Backlog items implement outdated milestone numbering.
- Any ticket references Hive as required core storage.
- Any ticket stores BYOK secrets outside secure storage.
- Any AI ticket omits validation/repair/review requirements.

## M1 — App Foundation + Local Data Spine

### Exit Criteria

- Flutter project boots on iOS and Android.
- Riverpod dependency graph is established and testable.
- Drift database initializes, migrates, and exposes repositories.
- `shared_preferences` wrapper exists for non-critical preferences only.
- `flutter_secure_storage` wrapper exists for secrets only.
- Logging and Crashlytics wrappers perform redaction by default.
- Environment/config system prevents debug-only behavior leaking into release.
- App can run in offline mode without crashing.

### Required Tests

- Fresh install database creation.
- Migration from schema 0 to current schema.
- Transaction rollback on failed multi-write.
- Secure storage store/read/delete fake key.
- Preferences wrapper rejects or prevents critical-data writes by code review/test convention.
- Crashlytics redaction unit tests with deliberately sensitive payload.

## M2 — Exercise Dataset Sync + Exercise Library

### Exit Criteria

- Firebase anonymous read-only sync path works.
- Dataset schema version is validated.
- Dataset is persisted locally in Drift.
- Compatible schema changes migrate where supported.
- Unsupported future schema shows update-required state.
- Exercise search/filter/detail screens work offline after sync.
- Videos fail gracefully; text remains available.
- Bodymap uses the 14-bucket contract.

### Required Tests

- First sync success.
- Sync failure with no dataset.
- Sync failure with existing dataset retained.
- Dataset checksum/version mismatch.
- Unknown muscle/category fixture behavior.
- Favorite/substitution flags persist locally.
- Bodymap tap target maps to correct filtered exercise list.

## M3 — Onboarding, Profile, Settings + BYOK Setup

### Exit Criteria

- User can complete onboarding within target flow.
- Profile writes canonical units.
- Equipment, goals, experience, schedule, substitutions, and limitations are stored correctly.
- BYOK provider setup stores key only in secure storage.
- Provider capability checks record supported text/json/image capabilities without exposing the key.
- Unsupported AI state disables AI-dependent flows with clear messaging.

### Required Tests

- Onboarding fresh user.
- Edit profile invalidates/regeneration prompt where applicable.
- Missing key state.
- Invalid key state.
- Key rotation.
- Provider capability refresh.
- Secrets absent from Drift/preferences/logs/Crashlytics.

## M4 — Manual Programmes, Workouts + Logging

### Exit Criteria

- User can create custom single workouts and multi-week programmes manually.
- Set-level prescriptions support warm-up and working sets.
- Manual supersets are supported for all experience levels.
- Active workout logging survives pause/background/restart where expected.
- Completed logs are immutable enough for analytics integrity, while corrections are controlled.
- Custom exercises can be created and used safely.

### Required Tests

- Create/edit/delete programme.
- Start active workout.
- Log sets with reps/weight/RPE/RIR/notes.
- Superset logging.
- Warm-up set logging.
- App kill during active workout.
- Custom exercise lifecycle.
- Transaction rollback if completion write fails.

## M5 — Analytics, PRs + Plateau Base Logic

### Exit Criteria

- Analytics read from completed working sets correctly.
- Warm-up sets are excluded from default analytics, PRs, e1RM, plateau detection, and progression triggers.
- PR logic handles weight/reps/bodyweight/time-based cases where in scope.
- Plateau detection creates deterministic candidates without needing AI.
- Charts render with empty, sparse, and dense data.

### Required Tests

- PR included/excluded fixtures.
- e1RM calculation fixtures.
- Plateau positive/negative fixtures.
- Week-over-week chart fixtures.
- Unit conversion display checks.
- Deleted workout effect on analytics.

## M6 — Progress Media Tracking

### Exit Criteria

- Users can capture/import front/back/left/right photos and/or short all-sides video.
- Media metadata is stored in Drift; raw media files remain file-based in app sandbox.
- Thumbnails are generated and linked correctly.
- Reminder cadence is requested only after first saved media session.
- Delete controls remove metadata and files according to retention rules.
- Progress media is not included in `.aedifyplan`, PDFs, external imports, Crashlytics, or default data-sharing paths.

### Required Tests

- Four-photo session.
- Video capture/import with duration cap.
- Thumbnail generation failure fallback.
- Reminder cadence creation/edit/off.
- Delete session file cleanup.
- Permission denied states.
- Low storage state.

## M7 — AI Infrastructure

### Exit Criteria

- AI provider abstraction supports configured v1 providers via BYOK.
- Capability gates are available before prompt assembly.
- Prompt builder composes correct modules and minimum context.
- Structured output validators reject invalid/malformed/unsafe responses.
- Repair flow attempts exactly one automatic repair where allowed.
- AI calls never log raw prompts/responses/keys/candidate lists.

### Required Tests

- Text model capability.
- JSON/schema mode capability.
- Image capability.
- Unsupported model path.
- Provider timeout/rate-limit/auth failure.
- Prompt context inclusion/exclusion snapshots.
- Validation/repair fixtures.

## M8 — AI Workout + Programme Generation

### Exit Criteria

- AI daily workouts and multi-week programmes are generated only after prerequisites pass.
- Generated outputs use valid local exercise IDs from candidate list.
- Beginner outputs remain simple and exclude AI-generated supersets.
- Non-beginner strength outputs include valid warm-up rules where required.
- Programme outputs are previewed and validated before save.
- Failed generation does not create partial durable programmes.

### Required Tests

- Beginner Path A/B fixtures.
- Non-beginner strength fixture.
- Strength + hypertrophy eligible fixture.
- Missing strength anchors needs-input fixture.
- Injury/substitution exclusion fixture.
- Invalid exercise ID rejection.
- Save preview gate cannot be skipped.

## M9 — AI Trainer Chat + AI Update Flows

### Exit Criteria

- Normal chat remains conversational and does not persist app-actionable content automatically.
- Save intent routes to structured workout/programme generation flow.
- Exercise swap, deload, plateau suggestions, and programme updates validate before applying.
- User can accept/reject AI changes.
- Updates are applied transactionally and can be inspected before save.

### Required Tests

- Chat no-save path.
- Explicit save workout path.
- Explicit save programme path.
- Swap valid/invalid candidate path.
- Deload update path.
- Plateau suggestion path.
- User rejects update; no data mutation.

## M10 — Local Sharing + PDF Export

### Exit Criteria

- `.aedifyplan` export validates against share schema.
- PDF export is human-readable and not importable.
- Export privacy modes work.
- Exports never include forbidden personal, AI, log, media, or source-reference data.
- Imports are inactive by default and create local editable copies.
- Custom exercises are recreated with new local IDs.

### Required Tests

- Template export.
- Exact prescription export with warning.
- PDF output with and without exercise appendix.
- Import valid `.aedifyplan`.
- Reject malformed/future unsupported share schema.
- Forbidden field injection rejected/stripped.

## M11 — External Text File Import

### Exit Criteria

- Supported text-based PDF/TXT/MD/XLSX/CSV imports extract locally.
- AI-processing consent appears before provider call.
- Only programme-relevant extracted content is sent.
- AI returns structured draft, not directly saved plan.
- Exercise matching requires ambiguous/unmatched resolution.
- Saved imported programmes are inactive by default.

### Required Tests

- Each supported file type.
- Unsupported/encrypted/corrupted/scanned PDF states.
- Ambiguous units.
- Ambiguous exercise match.
- Unmatched exercise create/remove/match path.
- Cancel before save leaves no active programme.

## M12 — Image/Screenshot External Import

### Exit Criteria

- Supported image selection works.
- Multiple images require/order screenshots.
- Local readability enhancement is content-preserving.
- Image-capable BYOK model gate blocks unsupported providers before prompt assembly.
- AI cannot invent unreadable/cropped content.
- Temporary original/enhanced images are cleaned after save/cancel according to lifecycle rules.

### Required Tests

- Single image import.
- Multi-image reorder.
- Blurry image warning.
- Cropped table missing-content flag.
- Unsupported model block.
- Artifact cleanup after save/cancel/failure.
- Forbidden image/source data not exported/logged.

## M13 — Optional AI Physique Analysis

### Exit Criteria

- User explicitly consents before selected media/frames are sent.
- Unsupported provider/model blocks analysis.
- Output is rough body-fat range with confidence, limitations, and training-focused feedback.
- Output avoids medical diagnosis, precise claims, attractiveness scoring, body shaming, and extreme diet advice.
- Analysis snapshots remain local and are excluded from sharing/export/default telemetry.

### Required Tests

- Analyze latest session.
- Compare baseline vs latest.
- Compare previous vs latest.
- Unsupported provider.
- Safety violation rejected/blocked.
- Delete analysis snapshot.
- Crash/export privacy checks.

## M14 — Privacy, Resilience + Release Hardening

### Exit Criteria

- Full privacy audit passes.
- Crashlytics redaction passes with deliberate sensitive test cases.
- All blocking defects closed.
- Private release build installs and runs on target devices.
- Fresh install and upgrade paths pass.
- Offline-first smoke test passes.
- Final sign-off checklist completed.

### Required Tests

- Full regression smoke.
- Platform permissions audit.
- Low storage and interrupted flow tests.
- Crashlytics console verification.
- Export/import privacy audit.
- Private distribution user limit check.
