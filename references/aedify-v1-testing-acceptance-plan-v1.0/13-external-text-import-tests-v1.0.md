## Goal

Validate AI-assisted import of external programmes/workouts from text-based files: PDF, TXT, MD, XLSX, and CSV. The import path must extract locally, obtain AI-processing consent, send only relevant content, receive a structured draft, validate/repair it, resolve exercises, preview it, and save inactive by default.

## Non-Negotiable Acceptance Principles

- No test may approve behavior that expands product scope beyond the re-locked PRD.
- Local-only/offline-first behavior must be proven for every non-AI feature.
- BYOK secrets must never appear in Drift, `shared_preferences`, local files, logs, Crashlytics, exports, screenshots generated by tests, or debug fixtures.
- Durable structured app data belongs in Drift/SQLite. Simple non-critical preferences may use `shared_preferences`. Secrets use `flutter_secure_storage` only.
- AI outputs are never trusted directly. They must pass schema validation, deterministic business-rule validation, exercise matching, privacy filtering, and user review where required.
- Crashlytics is allowed only for crash diagnostics with strict redaction.
- Imported workouts/programmes, AI-generated workouts/programmes, and shared plans must never bypass preview/review/validation gates.
- Progress media and physique-analysis data stay local by default and are excluded from normal export/share flows.

## Supported File Type Tests

| File Type | Required Cases |
|---|---|
| TXT | Simple workout, messy spacing, ambiguous units. |
| MD | Multi-week programme with headings/tables. |
| CSV | Workout rows, programme rows, missing columns, unit ambiguity. |
| XLSX | Multiple sheets, merged cells where extractor supports, empty sheets. |
| Text-based PDF | Extractable table, extractable text, long PDF. |

Unsupported/rejected:

- Encrypted PDF.
- Corrupted file.
- Cloud-only file unavailable locally.
- Scanned/image-only PDF for OCR path.
- Unsupported extension.
- Oversized file beyond local/import limits.

## Local Extraction Tests

For each supported format assert:

- Extraction happens locally before consent.
- User can review high-level file/source metadata before AI call.
- Extracted content is normalized into programme-relevant text/tables.
- Private unrelated file metadata is not sent.
- Extraction failure does not call AI.

Edge cases:

- Empty file.
- File with no workout/programme content.
- File with mixed nutrition/training notes.
- File with ambiguous units.
- File with copyrighted/source branding; app still must not store/export source excerpts.

## Consent Tests

Test cases:

1. User selects file and declines AI-processing consent.
2. User selects file and accepts consent.
3. User cancels after extraction but before AI.
4. User has no BYOK key.
5. User is offline.
6. Provider key invalid.

Expected:

- No AI call without consent.
- No extracted content is sent without consent.
- Missing/invalid BYOK blocks flow with clear setup path.
- Cancel leaves no imported programme.

## AI Parse Draft Tests

Required AI fixtures:

- Valid external programme import JSON.
- Valid external workout import JSON.
- Unknown type returns `needs_input`.
- Invalid JSON repairable.
- Invalid JSON non-repairable.
- Missing units.
- Missing exercise details.
- Supersets preserved where present.
- Warm-up/working sets preserved where present.
- Deload/progression notes preserved where present.
- AI attempts to adapt/personalize source without request.
- AI invents missing exercises/weeks.

Expected:

- Draft is not persisted as final plan until user review/save.
- Adaptation/personalization is rejected unless explicitly requested in later flow.
- Missing/unclear items appear for user resolution.

## Exercise Matching Tests

Matching stages:

1. Exact local name/alias match.
2. High-confidence deterministic match.
3. Ambiguous match requiring user confirmation.
4. Unmatched exercise requiring match, custom creation, or removal.
5. Optional AI match assistance for difficult unresolved names.

Test cases:

- Exact match auto-resolves.
- Fuzzy ambiguous match requires confirmation.
- Wrong high-confidence match prevented by threshold fixture.
- Unmatched custom exercise prefill reviewed by user.
- Remove unmatched exercise before save.
- Attempt save with unresolved exercise blocked.

## Save Tests

Scenarios:

- Save imported single workout.
- Save imported multi-week programme.
- Imported programme shorter than normal AI-generated minimum preserved.
- Imported item inactive by default.
- User activates imported programme later.
- App killed during import save transaction.
- Save fails halfway.

Expected:

- Transactional save.
- No active programme automatically created.
- No unresolved exercise references.
- Source file not stored by default.

## Privacy Tests

Forbidden persisted/exportable content:

- Original source file.
- Large source excerpts.
- AI extraction snapshot.
- Prompt text.
- Raw AI response.
- Private profile/log data unless later explicit adaptation flow.
- Source-reference content.

Test method:

- Seed source file with sentinel strings.
- Complete import/save/export.
- Search DB/export/log/Crashlytics test outputs.

Expected:

- Only validated local plan fields persist.
- Sentinels from source excerpts do not leak beyond allowed transient draft metadata.
